# 発見報告 機能仕様書（箕面倒木報告）

**状態:** 実装済み（2026-11-26。アプリの版 `app-shell-2026-11-26.5`）
**最終更新日:** 2026年11月26日

---

## 1. 概要

### 1.1 目的

倒木を見つけた人が、ハイキングマップの地図画面で撮った写真を選び、項目を入力して、報告書（PDF）を作る。
報告書は、山麓保全委員会 山林部会の「山林部会活動報告（ハイキング道倒木整備サポート）」の様式に沿う。

### 1.2 入口

起動時画面の「発見報告」ボタン（`#ftBtnFind`）。

### 1.3 決定事項（2026-11-26）

| 事項 | 決定 |
|---|---|
| 出力の形式 | 当面は PDF。将来 Excel に変えるか、Excel も出す可能性がある。そのときは PDF と別のファイルで出す（zip にまとめない） |
| 番号（様式の左上の「26-37」など） | 空欄で出力する。採番か入力にするときは、仕様を変える |
| 入力項目 | 様式の項目はすべて使う。どれも未入力でよい |
| 日時 | 選んだ写真の撮影日時の範囲を、「～」で区切って出す（→ [4.3](#43-日時の作り方)） |
| 通報先 | 顔ぶれはほぼ決まっているが確実ではないので、文字で入力する |
| 地図 | 1 枚。地図が 2 枚以上要る範囲の写真は、別の報告として扱う |
| 写真の番号 | 選んだ順に ①、②、… と付ける。通常は数枚で、最大 20 枚 |
| 報告書の保存 | 出力するだけで、アプリには保存しない。直すときは作り直す |

### 1.4 WebP・HTML・zip を選ばなかった理由

- **WebP:** 画像 1 枚なので、ページが増えると複数のファイルになる。古い Windows やメールソフトで開けないことがあり、報告書の印刷・保管に向かない。
- **HTML:** 添付ファイルとして、ウイルス対策で止められたり警告が出たりしやすい（行政あては特に）。スマホや LINE でも開きにくい。
- **Excel と PDF の zip:** 受け取った人がスマホで開くには展開が要る。多くの端末では、zip をスマホの共有メニュー（LINE・メール）で送れない。

## 2. 操作の流れ

```
起動時画面「発見報告」
  └─ ① 写真の選択 ──「次へ」──> ② 入力 ──「出力」──> ③ ファイル名の確認 ──> 共有 / 保存
           ↑                         │
           └──────「戻る」───────────┘
```

- 写真が 1 枚も無いときは、写真の選択を開かずに知らせる:
  「写真がありません。地図画面の「写真を撮影」で倒木の写真を撮ってください。」
- 入力から写真の選択に戻っても、選んだ写真と入力した内容は残る。
- 出力したあとも入力の画面は開いたままにする。直してもう一度出力できる（作り直し）。
- 「閉じる」（見出しの「×」も同じ）で発見報告を終える。選んだ写真と入力した内容は消える（→ [6](#6-保存するもの保存しないもの)）。
- 画面の外側（背景）を押しても閉じない。入力した内容をうっかり失わないため。

## 3. 写真の選択

| 項目 | 仕様 |
|---|---|
| 対象 | アプリの中の写真全部（地図画面の「写真を撮影」で撮ったものと、KMZ で読み込んだもの）。`photos.js` の `getPhotos()` |
| 並び | 写真の一覧と同じ順（撮影・読み込みの順） |
| 表示 | タイルの一覧。縮小画像・名前・撮影日時を出す（縮小画像は `getPhotoThumbUrl()`） |
| 選ぶ | タイルを押すと選ぶ。選んだ順の番号（①、②、…）をタイルに重ねて出す |
| 外す | 選んだタイルをもう一度押すと外す。後ろの番号を詰める（③ を外すと ④ が ③ になる） |
| 上限 | 20 枚。21 枚目を押したら「写真は 20 枚まで選べます」と知らせ、選ばない |
| 次へ | 1 枚以上選ぶと押せる |
| 写真への影響 | 写真の名前・位置・画像は変えない。消さない |

## 4. 入力

### 4.1 入力項目

どの項目も未入力でよい。未入力の欄は空欄のまま出力する。

| 様式の欄 | 入力のしかた | 初期値 | 出力 |
|---|---|---|---|
| 番号 | 入力しない | — | 空欄 |
| 日時 | 文字（1 行） | 写真の撮影日時の範囲（→ [4.3](#43-日時の作り方)） | そのまま |
| 天気 | 文字（1 行）。候補: 晴・曇・雨・雪 | 空 | そのまま |
| 気温 | 数字 | 空 | 「12℃」の形（空なら空欄） |
| 記入者 | 文字（1 行） | 前回の値 | そのまま |
| 対象案件 | 文字（1 行） | 空 | そのまま。ファイル名にも使う |
| 場所 | 文字（1 行）。下に参考を出す（→ [4.4](#44-場所の参考)） | 空 | そのまま |
| 通報先 | 文字（1 行）。例: 山パト/浦上 | 前回の値 | そのまま |
| 通報手段 | 文字（1 行）。候補: メール・電話・LINE | 前回の値 | そのまま |
| 通報日時 | 日付 | 今日 | 「2026/11/10」の形 |
| 参加者 | 文字（1 行） | 空 | そのまま |
| 活動内容 | 文字（複数行） | 空 | 活動内容の欄の本文 |
| 写真の見出し | 写真ごとに文字（1 行）。番号を前に付けて表示する | 写真の名前。既定の名前（「写真3」など）のままの写真は空 | 「①しらみ地蔵～C20」の形（空なら「①」だけ） |
| 通報先へ連絡 | 要・不要・どちらでもない（未選択）から選ぶ | 未選択 | 選んだ方を丸で囲む |
| 行政への連絡 | 要・不要・どちらでもない（未選択）から選ぶ | 未選択 | 選んだ方を丸で囲む |
| 連絡事項 | 文字（複数行） | 空 | 連絡事項の欄の本文 |

### 4.2 前回の値を覚える項目

- 記入者・通報先・通報手段は、出力したとき（共有・保存を押したとき）の値を覚え、次の発見報告の初期値にする。
- 保存先は localStorage のキー `ft-report.found.lastInputs`（JSON）。
- 報告書そのものや、ほかの項目は覚えない。

### 4.3 日時の作り方

選んだ写真のうち、撮影日時が分かるものの最も早い日時と最も遅い日時から作る（選んだ順には関係しない）。秒は出さない。

| 場合 | 出力の例 |
|---|---|
| 同じ日 | `2026/11/09(日) 10:15～11:40` |
| 日をまたぐ | `2026/11/09(日) 15:30～2026/11/10(月) 09:05` |
| 1 枚だけ、または全部同じ時刻 | `2026/11/09(日) 10:15` |
| 撮影日時が分かる写真が無い（他のアプリの KMZ から読んだ写真など） | 空欄 |

- 写真を選び直したら、作り直して日時の欄に入れ直す。手で書き換えていた場合も入れ直す。

### 4.4 場所の参考

- 場所の欄の下に、写真ごとに最も近い緊急ポイントを参考として出す。
  - 例: `① C-20 しらみ地蔵（約 40m）`
- 1 km 以内に緊急ポイントが無い写真は、「① 近くに緊急ポイントなし」とする。
- 参考は表示するだけで、報告書には出さない。場所の欄は利用者が書く。
- 緊急ポイントは、公開データの地図データ（`type` が `ポイントGPS` のもの。`id` が番号、`name` が名前）を使う。
  - 地図データは、`config.js` の `MAPDATA_CACHE`・`MAPDATA_API_URL` で Cache API から読む。
  - 地図データがまだ無い（一度も取得していない）ときは、参考を出さない。

### 4.5 地図の範囲の注意

- 選んだ写真が全部入る地図の縮尺が小さすぎるとき（ズームが 14 未満になるとき）は、入力の画面に次の注意を出す。
  「写真の範囲が広いため、地図の縮尺が小さくなります。地図は 1 枚なので、必要なら報告を分けてください。」
- 注意を出すだけで、出力はできる。

## 5. 報告書（PDF）

### 5.1 体裁

| 項目 | 仕様 |
|---|---|
| 用紙 | A4 縦 |
| 作り方 | ページを 1 枚の画像として描き（1654×2339 px。200dpi 相当）、JPEG にして PDF に入れる |
| 文字 | スマホの日本語の字体で描く。PDF に字体を入れないので、日本語の字体を別に用意しなくてよい |
| 制約 | 文字は画像になるため、PDF の文字の選択・コピー・検索はできない |
| PDF の組み立て | ライブラリを使わずに作る（JPEG の画像のページを並べるだけの PDF） |

### 5.2 配置

様式（山林部会活動報告）に合わせる。配置は後で調整してよい。

- 表の列の幅・欄の組み方・色・罫線は、利用者から受け取った様式の元の Excel に合わせた（Excel は実在の人の名前と報告の中身を含むため、リポジトリには置かない）。
  - 列 A=11（欄の名前）、B=1.11（すき間）、C〜L=8.78 ずつ、M=9.22 の比で、表の幅（約 182mm）を割り付ける。
  - 欄の組み方: 日時 B〜G／天気 H／I／気温 J／K／記入者 L／M、対象案件 B〜G／場所 H／I〜M、通報先 B〜E／通報手段 F／G〜I／通報日時 J／K〜M、参加者 B〜M。
  - 欄の名前の地は `#EEECE1`、「通報先へ連絡」「行政への連絡」の地は薄い緑、見出しの下は太線、活動内容・連絡事項の欄は点線の罫線。
- 字は様式（Meiryo UI 11pt を 85% で印刷）より少し大きくした（スマホで読みやすくするため）。欄の値が欄の幅に入らないときは折り返し、行を高くする。欄の名前が入らないときは字を小さくする。

**1 ページ目の上部（表）**

| 行 | 欄 |
|---|---|
| 見出し | 左上に番号の枠（緑の地。空欄）、右に「山麓保全委員会　山林部会活動報告（ハイキング道倒木整備サポート）」 |
| 1 | 日時 ／ 天気 ／ 気温 ／ 記入者 |
| 2 | 対象案件 ／ 場所 |
| 3 | 通報先 ／ 通報手段 ／ 通報日時 |
| 4 | 参加者 |

**活動内容の欄（表の下に、次の順で流し込む）**

1. 本文（活動内容）。欄の幅で折り返す。
2. 地図（→ [5.3](#53-地図)）。欄の幅いっぱい、縦横比 3:2。
3. 写真。1 行に 3 枚。各写真の上に見出し（「①しらみ地蔵～C20」）。写真は縦横比を保って枠に収める。

**連絡事項の欄（最後のページの末尾）**

- 「通報先へ連絡　要　不要」「行政への連絡　要　不要」。選んだ方を丸で囲む（様式と同じ）。
- 連絡事項の本文。欄の幅で折り返す。

**ページの送り**

- 1 ページに収まらない分は、次のページに送る。本文は行の途中で、写真は行ごとに送る。地図は分けない。
- 2 ページ目以降の上部には、「山林部会活動報告（続き）」と対象案件を出す。
- どのページも下に「1 / 3」の形でページ番号を出す。
- 写真 20 枚・本文が短い場合で、3 ページ程度を想定する。

### 5.3 地図

| 項目 | 仕様 |
|---|---|
| 地図 | 地理院タイル（標準地図）。`config.js` の `TILE_URL_BASE` |
| 範囲 | 選んだ写真が全部入る範囲に余白を足す。ズームの上限は 17（写真が 1 枚・近いときに拡大しすぎない） |
| 写真の位置 | 番号付きの丸（オレンジの丸の中に 1、2、…。①、②、… と同じ番号）。小さい番号を上に重ねる |
| 緊急ポイント | 地図の範囲にあるものを、小さな印と番号（`C-20` など）で描く。縮尺が小さい地図では密集して読めなくなるため、番号はズーム 14 以上、印はズーム 12 以上のときだけ描く |
| ハイキングルート | 地図データのルートの線を描く |
| 縮尺 | 縮尺の目安（スケールバー） |
| 出典 | 右下に「出典：国土地理院」 |
| 表示設定との関係 | マップ画面の表示設定（各レイヤーの表示・非表示）に関係なく、上のものを描く |
| オフライン | ダウンロード済みのタイルを使う。取れないタイルは灰色にし、出力のときに「地図の一部を取得できませんでした」と知らせる |
| 写真の印の重なり | 同じ場所の写真は印が重なる（ずらさない。後で必要なら見直す） |

- 地図の画像は、タイルを `fetch` で取り、画像の上に描いて作る。マップ画面のタイルは `crossOrigin` 付きで読んでいるため、ダウンロード済みのタイルも画像に描ける。

### 5.4 ファイル名と渡し方

| 項目 | 仕様 |
|---|---|
| 既定のファイル名 | `山麓保全委員会 山林部会活動報告書 {対象案件}.pdf` |
| 対象案件が空のとき | `山麓保全委員会 山林部会活動報告書 {通報日時 YYYYMMDD}.pdf`（通報日時も空なら今日の日付） |
| ファイル名の確認 | 出力の前にファイル名を表示し、書き換えられるようにする |
| 使えない文字 | `\ / : * ? " < > |` は `_` に置き換える |
| 共有 | スマホの共有メニュー（Web Share API）で PDF を渡す（LINE・メールなど）。共有メニューで PDF を渡せない端末では、このボタンを出さない。渡し終えたら「報告書を共有しました」と知らせる。共有メニューを閉じたときは、ファイル名の確認に戻る |
| 保存 | 端末に保存する（ダウンロード。`file-export.js` の `downloadBlob`）。保存されたかどうかはアプリに分からないので、完了の知らせは出さない（GPX・KMZ の出力と同じ） |
| 作っている間 | 「報告書を作っています」と出し、操作を受け付けない。PDF は「出力」を押したときに作り、ファイル名の確認を開く（共有の画面は、押した操作の中で待たずに開く必要があるため） |

## 6. 保存するもの・保存しないもの

- 報告書と入力した内容は、アプリに保存しない。発見報告を閉じると消える。
- 例外として、記入者・通報先・通報手段だけは、次の初期値として覚える（→ [4.2](#42-前回の値を覚える項目)）。
- 写真は変えない・消さない。
- アプリが報告書をどこかへ送ることはない。送るのは利用者で、共有メニューやメールを使う。そのため、「外部へ送信しない」趣旨の記述（CLAUDE.md の同名の節）とは矛盾しない。

## 7. 対象外・今後の検討

| 事項 | 扱い |
|---|---|
| 番号の採番・入力 | 今は空欄。決まったら仕様を変える |
| Excel の出力 | 今後。PDF と別のファイルで出す。様式の元の Excel ファイルに値と写真を入れる形を検討する（そのときに、利用者から元の Excel を受け取る） |
| 地図 2 枚以上 | 別の報告として扱う（この機能では作らない） |
| 報告書の保存・再編集 | しない（作り直す） |
| 英語の表示 | しない（ft-report は日本語のみ） |

## 8. 実装の構成

- ft-report の処理はすべて `public/js/ft/` の `ft-` のファイルに置き、minoh-hiking 由来のファイルは書き換えない。
- 画面（写真の選択・入力・ファイル名の確認）は JS で作る（index.html は書き換えない）。
- 報告書の中身を組み立てる処理と、PDF に配置する処理を分ける。後で Excel の出力を足すときに、中身の組み立てを使い回すため。
- 「処理報告」も同じ様式を使う見込みなので、様式の配置・地図・PDF は `ft-report-` の名前の共通部品にする。

| ファイル | 役割 |
|---|---|
| `public/js/ft/ft-main.js` | 起動時画面の「発見報告」ボタンから `ft-found.js` の `openFoundReport()` を呼ぶ |
| `public/js/ft/ft-found.js` | 発見報告の画面と流れ（写真の選択・入力・出力）。画面は開くたびに作り、閉じたら取り除く |
| `public/js/ft/ft-report-data.js` | 入力と写真から報告書の中身（項目・日時・写真の並び）を組み立てる。PDF・Excel で共通 |
| `public/js/ft/ft-report-layout.js` | 様式の配置。ページの画像を描く |
| `public/js/ft/ft-report-map.js` | 地図の画像（タイル・写真の印・緊急ポイント・ルート・縮尺・出典） |
| `public/js/ft/ft-pdf.js` | PDF の組み立て（JPEG のページを並べる） |
| `public/css/ft-style.css` | 画面のスタイル |

- 新しい JS は、`service-worker.js` の `SHELL_LOCAL_PATHS` の「ft-report 専用」の区画に足し、版名を上げる。
- 使う既存の部品（minoh-hiking 由来。書き換えない）:

| 部品 | 用途 |
|---|---|
| `photos.js` の `getPhotos()`・`getPhotoThumbUrl()` | 写真（`id`・`name`・`timeMs`・`lat`・`lng`・`blob`）と縮小画像 |
| `config.js` の `MAPDATA_CACHE`・`MAPDATA_API_URL`・`TILE_URL_BASE` | 地図データ（緊急ポイント・ルート）と地理院タイル |
| `file-export.js` の `downloadBlob()` | 端末への保存 |
| `messages.js` の `showToast()` | 知らせ |
| `update.js` の `checkAppShellUpdate()`・`published-data.js` の `checkPublishedDataUpdate()` | 起動時画面のボタンを押したときの更新版の確認（既存のボタンと同じ） |
| `style.css` の `.modal`・`.photo-list-tile`・`.btn`・`.blocking-overlay` など | 画面の部品の見た目（足した部品のスタイルは `ft-style.css`） |
